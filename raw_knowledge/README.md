# 原始知识资料库

> 本文件夹用于存放收集到的原始知识资料，AI 会将这些原始资料转换为结构化的知识库内容。

---

## 📁 文件夹结构

```
raw_knowledge/
├── README.md                    # 本文档
├── QUICK_START.md               # 快速开始指南
│
├── mixed/                       # 混合内容的原始资料 ⭐推荐
│   ├── 综合文档.docx           # 包含多种类型内容
│   ├── 数据需求.xlsx           # 业务+数据混合
│   └── ...                     # 不确定放哪里？放这里！
│
├── business/                    # 纯业务相关原始资料（可选）
│   ├── 术语表.xlsx             # 业务术语
│   ├── 指标定义.docx           # 指标说明文档
│   └── ...
│
├── data_assets/                 # 纯数据资产相关原始资料（可选）
│   ├── 数据字典.xlsx           # 表结构和字段说明
│   ├── DDL.sql                 # 建表语句
│   └── ...
│
├── sql_examples/                # 纯 SQL 案例相关原始资料（可选）
│   ├── 常用查询.sql            # SQL 查询语句
│   ├── 需求文档.docx           # 业务需求文档
│   └── ...
│
└── processed/                   # 已处理的原始资料（存档）
    ├── 2024-01/
    ├── 2024-02/
    └── ...
```

**💡 提示**: 
- 如果你的文件**只包含一种类型**的内容，可以直接放到对应的文件夹
- 如果你的文件**包含多种类型**的内容，或者**不确定放哪里**，直接放到 `mixed/` 文件夹
- AI 会自动识别和分类内容，无需手动区分

---

## 🎯 使用流程

### 步骤 1: 放置原始资料

将收集到的原始知识资料放到对应的文件夹中：

**方式 1: 不确定放哪里？直接放到 `mixed/`** ⭐推荐

- **任何类型的文件** → `raw_knowledge/mixed/`
  - 综合性文档、数据需求、分析报告等
  - AI 会自动识别内容类型并分类处理
  - **这是最简单的方式，不需要你自己判断！**

**方式 2: 如果很明确是单一类型，可以放到对应文件夹**（可选）

- **纯业务知识** → `raw_knowledge/business/`
  - 术语表、指标定义、业务规则、计算公式等
  
- **纯数据资产** → `raw_knowledge/data_assets/`
  - 数据字典、表结构、DDL、数据血缘等
  
- **纯 SQL 案例** → `raw_knowledge/sql_examples/`
  - SQL 查询、需求文档、分析报告等

**💡 提示**: 推荐使用方式 1，简单省心！

### 步骤 2: 通知 AI 处理

在 Cursor 中告诉 AI：

```
请处理 raw_knowledge/business/术语表.xlsx，将其转换为知识库内容
```

或者：

```
我放了新的原始资料在 raw_knowledge/ 中，请帮我处理
```

### 步骤 3: AI 自动转换

AI 会：
1. ✅ 读取原始资料
2. ✅ 分析内容结构
3. ✅ 转换为标准的知识库格式
4. ✅ 生成对应的 `.md` 文件到 `knowledge/` 目录
5. ✅ 将原始资料移动到 `processed/` 存档

### 步骤 4: 审核和调整

检查生成的知识库内容，如有需要可以：
- 补充缺失的信息
- 修正错误的理解
- 调整格式和结构

## 🔄 转换规则

### 业务知识转换

**原始资料** → **知识库文件**

- 术语表 → `knowledge/business/glossary.md`
- 指标定义 → `knowledge/business/metrics/{指标类型}_metrics.md`
- 维度定义 → `knowledge/business/dimensions/{维度类型}_dimensions.md`
- 计算规则 → `knowledge/business/calculation_rules/{规则名称}.md`

**转换标准**:
1. 提取所有术语和定义
2. 标准化格式（使用模板）
3. 添加分类和标签
4. 补充示例和说明
5. 标注来源和更新时间

### 数据资产转换

**原始资料** → **知识库文件**

- 数据字典 → `knowledge/data_assets/tables/{层级}/{表名}.md`
- 表关系图 → 文字描述 + `knowledge/data_assets/relationships.md`
- DDL 语句 → 提取字段信息到表文档

**转换标准**:
1. 按照表模板 (`TABLE_TEMPLATE.md`) 组织
2. 提取所有字段和类型
3. 补充字段说明和约束
4. 添加分区信息
5. 说明使用场景

### SQL 案例转换

**原始资料** → **知识库文件**

- SQL 查询 → `knowledge/sql_examples/{分类}/{案例名称}.md`
- 需求文档 → 提取需求到 SQL 案例的"业务需求"部分
- 分析报告 → 提取分析逻辑到案例说明

**转换标准**:
1. 按照案例模板 (`EXAMPLE_TEMPLATE.md`) 组织
2. 提取业务需求
3. 记录需求澄清过程
4. 补充技术方案说明
5. 添加结果解释
6. **将 SQL 转换为 Trino 语法**

## 📝 原始资料命名规范

### 推荐命名格式

```
{类型}_{内容描述}_{版本/日期}.{扩展名}

示例:
- 术语表_雪球业务术语_v1.0.xlsx
- 数据字典_用户表_20240101.xlsx
- SQL案例_DAU统计_最新.sql
- 指标定义_用户指标_2024Q1.docx
```

### 命名原则

1. **清晰描述**: 文件名要能看出内容
2. **添加版本**: 便于追踪更新
3. **避免特殊字符**: 不要使用空格、中文标点
4. **统一格式**: 同类文件使用相同命名格式

**💡 提示**: 不用纠结分类，文件名描述清楚内容即可，AI 会自动识别！

## 🎨 原始资料质量要求

### 高质量资料的特征

✅ **内容完整**
- 有明确的定义和说明
- 包含示例和场景
- 有版本和更新时间

✅ **结构清晰**
- Excel 有表头
- Word 有章节标题
- SQL 有注释

✅ **信息准确**
- 定义准确无歧义
- 数据类型正确
- SQL 语法正确

✅ **来源可靠**
- 官方文档
- 权威人员提供
- 经过验证

### 不同质量资料的处理

| 质量等级 | 特征 | AI 处理方式 |
|---------|------|-----------|
| ⭐⭐⭐⭐⭐ 优秀 | 完整、准确、结构化 | 直接转换 |
| ⭐⭐⭐⭐ 良好 | 大部分完整，少量缺失 | 转换 + 标注缺失项 |
| ⭐⭐⭐ 一般 | 信息不完整，需要补充 | 部分转换 + 提出问题 |
| ⭐⭐ 较差 | 结构混乱，信息缺失严重 | 整理建议 + 等待补充 |
| ⭐ 很差 | 无法理解或错误严重 | 拒绝处理 + 说明原因 |

## ⚠️ 注意事项

### 1. 敏感信息

- ❌ 不要上传包含真实用户数据的文件
- ❌ 不要上传包含密码、密钥的文件
- ✅ 使用脱敏后的示例数据
- ✅ 使用假数据进行示例

### 2. 文件大小

- ✅ 推荐：< 10MB 的单个文件
- ⚠️ 谨慎：10-50MB 的文件（可能处理较慢）
- ❌ 避免：> 50MB 的文件（建议拆分）

### 3. 文件格式

- ✅ 优先使用结构化格式（Excel、Markdown、SQL）
- ⚠️ 图片格式需要人工辅助说明
- ❌ 避免使用加密或压缩文件

### 4. 版本管理

- ✅ 保留原始文件的版本信息
- ✅ 在 processed/ 中按日期归档
- ✅ 记录处理日志

## 🤖 AI 处理能力

### AI 能做什么

✅ **自动提取**
- 从 Excel 提取术语、指标、字段
- 从 SQL 提取查询逻辑和表关系
- 从文档提取业务规则和定义

✅ **格式转换**
- 将原始资料转换为标准的 Markdown 格式
- 按照模板组织内容结构
- 补充必要的章节和说明

✅ **语法转换**
- 将 MySQL/Hive SQL 转换为 Trino 语法
- 修正常见的语法错误
- 添加必要的注释

✅ **质量检查**
- 检查内容完整性
- 验证逻辑正确性
- 标注缺失项和疑问

### AI 不能做什么

❌ **理解业务语境**
- 无法完全理解业务背景
- 需要人工确认业务定义

❌ **填补缺失信息**
- 不能臆造不存在的信息
- 需要人工补充缺失的内容

❌ **验证业务正确性**
- 不能判断业务规则是否正确
- 需要业务专家审核

## 📞 问题反馈

如果在使用过程中遇到问题：

1. **AI 无法理解原始资料**
   - 检查文件格式是否支持
   - 尝试整理为更结构化的格式
   - 提供额外的背景说明

2. **转换结果不准确**
   - 指出具体的错误
   - 提供正确的理解
   - AI 会重新处理

3. **缺失重要信息**
   - 补充到原始资料中
   - 或在处理后手动添加
   - 更新知识库
