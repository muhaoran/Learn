# 原始知识处理 - 设计哲学

> 为什么我们这样设计？核心理念是什么？

---

## 🎯 核心理念

### 1. 极简主义 - 用户只需做 3 件事

```
1. 放文件 → raw_knowledge/mixed/
2. 说一句 → "请处理"
3. 确认 → AI 标注的不确定项
```

**不需要**：
- ❌ 学习复杂的格式
- ❌ 整理文档结构
- ❌ 标注内容类型
- ❌ 区分术语和表
- ❌ 转换 SQL 语法
- ❌ 判断放哪个文件夹

### 2. 智能优先 - AI 做所有复杂的事

**AI 的职责**：
- ✅ 识别内容类型
- ✅ 提取关键信息
- ✅ 补全不完整内容
- ✅ 推理关联关系
- ✅ 转换为标准格式
- ✅ 生成知识库文件

**用户的职责**：
- ✅ 提供原始资料
- ✅ 确认不确定项

### 3. 容错性 - 任何质量都能处理

| 文档质量 | 传统系统 | 我们的系统 |
|---------|---------|-----------|
| ⭐⭐⭐⭐⭐ 完美 | ✅ 可处理 | ✅ 完美处理 |
| ⭐⭐⭐⭐ 良好 | ✅ 可处理 | ✅ 自动处理 + 标注缺失 |
| ⭐⭐⭐ 一般 | ⚠️ 需要整理 | ✅ 提取有用信息 + 提问 |
| ⭐⭐ 较差 | ❌ 无法处理 | ✅ 尽力提取 + 请求澄清 |
| ⭐ 很差 | ❌ 无法处理 | ⚠️ 建议整理 |

**关键**：即使质量很低，也能提取部分有用信息。

### 4. 渐进式 - 从不完美到完美

```
第一次处理（质量低）
    ↓
提取部分信息 + 标注缺失
    ↓
用户补充缺失信息
    ↓
重新处理（质量提升）
    ↓
知识库逐步完善
```

**不要求一次完美**，允许逐步改进。

## 🧠 技术理念

### 1. 语义理解 > 格式匹配

**传统方式**（基于格式）：
```
需要：
- 固定的表头
- 特定的字段名
- 标准的格式

如果格式不对 → 无法处理
```

**我们的方式**（基于语义）：
```
理解：
- "DAU 是日活" → 术语定义
- "user_behavior 表" → 数据表
- "SELECT COUNT..." → SQL 查询

格式混乱也能理解 → 智能处理
```

### 2. 智能补全 > 严格要求

**传统方式**：
```
SQL 不完整 → 报错
表名不规范 → 报错
字段缺少类型 → 报错
```

**我们的方式**：
```
SQL 不完整 → 智能补全
表名不规范 → 推测标准名
字段缺少类型 → 推测类型 + 标注
```

### 3. 置信度标注 > 二元判断

**传统方式**：
```
对 or 错
能处理 or 不能处理
```

**我们的方式**：
```
高置信度 → 直接使用
中置信度 → 使用 + 标注
低置信度 → 标注 + 请求确认
```

## 🎨 用户体验理念

### 1. 降低认知负担

**不要让用户思考**：
- ❓ 这个文件应该放哪里？
- ❓ 这是术语还是指标？
- ❓ 需要什么格式？
- ❓ SQL 语法对不对？

**让 AI 思考**：
- ✅ AI 判断文件类型
- ✅ AI 识别内容类型
- ✅ AI 处理格式问题
- ✅ AI 转换 SQL 语法

### 2. 即时反馈

**处理后立即告诉用户**：
```markdown
✅ 识别出 3 种类型的内容
✅ 生成了 5 个知识库文件
⚠️ 有 2 个地方需要确认
```

**不是**：
```
处理完成（没有任何说明）
```

### 3. 可追溯性

**每个生成的文件都标注**：
- 来源：哪个原始文件
- 时间：什么时候处理的
- 置信度：AI 有多确定
- 不确定项：哪些需要确认

## 💡 设计决策

### 为什么创建 `mixed/` 文件夹？

**问题**：用户不知道文件应该放哪里
- 这个文件是业务的还是数据的？
- 如果包含多种内容怎么办？

**解决**：创建 `mixed/` 文件夹
- ✅ 不确定？放这里！
- ✅ 混合内容？放这里！
- ✅ AI 自动识别和分类

### 为什么不要求用户标注？

**问题**：标注增加用户负担
- 需要理解什么是术语、什么是表
- 需要学习标注格式
- 容易标注错误

**解决**：AI 自动识别
- ✅ 用户不需要理解分类
- ✅ 不需要学习标注
- ✅ AI 负责识别和分类

### 为什么支持低质量文档？

**问题**：现实中的文档往往质量不高
- 会议记录、聊天记录
- 口语化描述
- 信息不完整

**解决**：智能提取 + 补全
- ✅ 从混乱中提取有用信息
- ✅ 补全不完整的内容
- ✅ 标注不确定的部分

### 为什么要标注置信度？

**问题**：AI 不是 100% 准确
- 可能理解错误
- 可能遗漏信息
- 可能推测错误

**解决**：标注置信度
- ✅ 让用户知道哪些是确定的
- ✅ 让用户知道哪些需要确认
- ✅ 建立信任

- ✅ 不需要看复杂的文档

- ✅ 支持多种格式

### 1. 简单至上
**复杂留给 AI，简单留给用户**

**能自动的就不要手动**

**每个决策都有依据**

### 6. 持续优化
**从反馈中学习和改进**
