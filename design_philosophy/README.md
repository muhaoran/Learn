## 🎯 设计原则（总览）

### 核心原则

1. **知识驱动** - AI 的能力来自知识库，不是"智能"本身
2. **用户至上** - 降低使用门槛，提升用户体验
3. **准确第一** - 宁可澄清也不臆测
4. **可追溯** - 每个决策都有依据
5. **可进化** - 系统能够持续学习和优化

### 设计哲学

```
简单 > 复杂
明确 > 模糊
标准化 > 个性化
可维护 > 功能丰富
```

## 🏗️ 系统架构层次

### 层次关系

```
用户层（User Layer）
    ↓ 提交需求
需求理解层（Understanding Layer）
    ↓ 解析和澄清
知识层（Knowledge Layer）
    ↓ 提供业务和数据知识
生成层（Generation Layer）
    ↓ 生成 SQL
验证层（Validation Layer）
    ↓ 验证正确性
输出层（Output Layer）
    ↓ 返回结果和解释
```

## 💡 设计原则详解

### 1. 知识驱动

**理念**: AI 的能力 = 知识库的质量

**体现**:
- 所有 SQL 生成都基于知识库
- 不允许 AI 臆测业务规则
- 知识库缺失时明确告知

**好处**:
- 准确率可控
- 结果可解释
- 持续改进

### 2. 用户至上

**理念**: 让用户感觉不到系统的复杂性

**体现**:
- raw_knowledge/mixed/ 自动识别
- 不需要用户标注
- 不需要用户区分

**好处**:
- 使用门槛低
- 用户愿意用
- 快速推广

### 3. 准确第一

**理念**: 宁可澄清也不臆测

**体现**:
- 遇到模糊需求主动提问
- 标注不确定的地方
- 提供选项让用户选择

**好处**:
- 避免错误
- 建立信任
- 提升质量

### 4. 可追溯

**理念**: 每个决策都有依据

**体现**:
- 知识来源标注
- 引用关系清晰
- 处理日志完整

**好处**:
- 便于审查
- 便于优化
- 便于学习

### 5. 可进化

**理念**: 系统能够持续学习

**体现**:
- 反馈收集机制
- 知识更新流程
- 案例积累

**好处**:
- 持续改进
- 准确率提升
- 知识增长

## 🎓 设计的本质

> **"好的设计不是加法，而是减法"**

- 不是功能越多越好
- 而是用户觉得越简单越好

> **"好的设计是透明的"**

- 不是隐藏复杂性
- 而是让复杂性变得可理解

> **"好的设计是可进化的"**

- 不是一次定型
- 而是持续优化
