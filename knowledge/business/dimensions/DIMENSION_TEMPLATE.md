# 维度定义模板

> 本文档是维度定义的标准模板，定义了如何规范地添加和描述维度。

---

## 📋 模板说明

### 什么是维度？

**维度**是观察和分析数据的**角度或切面**，是数据分析中的"分组"和"筛选"依据。

**特征**：
- ✅ 定义数据的观察角度（如时间、地域、用户类型）
- ✅ 有明确的分类规则
- ✅ 可以用于 GROUP BY 和 WHERE
- ✅ 引用术语表的概念
- ✅ 被指标定义使用

**不是什么**：
- ❌ 不是指标（维度是角度，指标是度量）
- ❌ 不是术语（维度是分类，术语是概念）

**示例**：
- ✅ "时间维度：日/周/月" - 是维度（观察角度）
- ✅ "用户类型：新用户/老用户" - 是维度（分类角度）
- ❌ "DAU" - 是指标，不是维度

### 为什么需要维度定义？

1. **统一分类标准** - 让所有人用相同的方式分类数据
2. **明确分组规则** - 定义如何将数据分组
3. **提供 SQL 实现** - 告诉 AI 如何在 SQL 中实现
4. **支持多维分析** - 多个维度可以组合使用

## 📖 字段详细说明

### 1. 维度名称

**是什么**: 维度的正式名称

**怎么写**:
- ✅ 简洁、明确
- ✅ 能体现观察角度
- ✅ 避免与指标混淆

**示例**:
- ✅ "新老用户"（维度）
- ✅ "注册渠道"（维度）
- ❌ "新增用户数"（这是指标，不是维度）

### 2. 维度类型

**是什么**: 维度的分类

**常见类型**:
- **时间维度**: 日、周、月、季度、年
- **用户维度**: 新老用户、用户等级、活跃度分层
- **地域维度**: 省份、城市、地区
- **渠道维度**: 注册渠道、来源渠道
- **内容维度**: 内容类型、内容标签
- **产品维度**: 功能模块、产品线

### 3. 分类规则 ⭐核心

**什么是"分类规则"？**

分类规则定义了如何将数据划分到不同的类别中。

**必须明确的要素**：

1. **分类方式**
   - 按什么标准分类？
   - 示例："按注册时间距今的天数分类"

2. **类别列表**（必须穷尽）
   - 有哪些类别？
   - 每个类别的判断条件是什么？
   - 示例：
     ```
     新用户: 注册时间 <= 30天
     老用户: 注册时间 > 30天
     ```

3. **互斥性**
   - 各类别是否互斥？
   - 一个数据能否属于多个类别？
   - 通常应该互斥（一个用户只能是新用户或老用户）

4. **穷尽性**
   - 是否覆盖所有情况？
   - 有没有遗漏的情况？
   - 如果有遗漏，如何处理？

5. **边界处理**
   - 边界值属于哪个类别？
   - 示例："注册时间 = 30天"算新用户还是老用户？

6. **默认值**
   - 无法判断时归为哪个类别？
   - 示例："注册时间为 NULL"时如何处理？

**完整示例**:
```markdown
**分类规则**:

**分类方式**: 按用户注册时间距今的天数分类

**类别列表**:

| 类别名称 | 判断条件 | 说明 | 示例 |
|---------|---------|------|------|
| 新用户 | date_diff('day', register_date, current_date) <= 30 | 注册30天内 | 注册20天 |
| 老用户 | date_diff('day', register_date, current_date) > 30 | 注册超过30天 | 注册100天 |

**分类特性**:
- **互斥性**: ✅ 是（一个用户只能是新用户或老用户）
- **穷尽性**: ✅ 是（所有用户都能分类）
- **默认值**: 如果 register_date 为 NULL，归为"未知"类别

**边界处理**:
- 注册时间 = 30天：算新用户（<= 30天）
- 注册时间 = 30.5天：算老用户（> 30天）
```

### 4. 数据实现 ⭐核心

**什么是"数据实现"？**

数据实现说明这个维度在数据库中如何体现，以及在 SQL 中如何使用。

**必须包含**：

1. **数据字段**
   - 字段名是什么？
   - 字段类型是什么？
   - 在哪些表中？

2. **SQL 实现**
   - 如何在 SQL 中使用这个维度？
   - 如果需要计算，如何计算？
   - 使用 Trino 语法

**两种情况**：

**情况1: 字段已存在**
```markdown
**数据字段**: 
- **字段名**: register_channel
- **字段类型**: varchar(50)
- **取值范围**: 'iOS', 'Android', 'Web', 'H5'
- **所在表**: dwd_user_register, dws_user_daily

**SQL 实现**:
```sql
-- 直接使用字段
SELECT 
    register_channel,  -- 维度字段
    COUNT(DISTINCT user_id) as user_count
FROM 
    dwd_user_register
GROUP BY 
    register_channel;  -- 按维度分组
```
```

**情况2: 需要计算**
```markdown
**数据字段**: 
- **基础字段**: register_date
- **字段类型**: date
- **所在表**: dwd_user_register

**SQL 实现**:
```sql
-- 通过计算得出维度值
SELECT 
    CASE 
        WHEN date_diff('day', register_date, current_date) <= 30 
        THEN '新用户'
        ELSE '老用户'
    END as user_type,  -- 计算得出的维度
    COUNT(DISTINCT user_id) as user_count
FROM 
    dwd_user_register
GROUP BY 
    user_type;
```
```

## 📝 完整示例

### 示例 1: 时间维度 - 日

```markdown
## 日（Day）

### 基本信息

**维度名称**: 日

**英文名称**: Day

**维度类型**: 时间维度

**别名**: 
- 天
- 自然日
- 日期

### 定义

**标准定义**: 
自然日，从 00:00:00 到 23:59:59 的 24 小时时间段。

**业务含义**: 
日是最细粒度的时间维度，用于观察数据的每日变化，是日报、日常监控的基础。

**引用的术语**: 
- 无（时间维度是基础维度，不引用其他术语）

### 分类规则

**分类方式**: 按自然日划分

**类别列表**: 

每个自然日是一个类别，格式为 YYYY-MM-DD

**分类特性**:
- **互斥性**: ✅ 是（一个时间点只属于一个自然日）
- **穷尽性**: ✅ 是（所有时间都能归到某个自然日）
- **默认值**: 不适用

**边界处理**:
- 23:59:59 属于当天
- 00:00:00 属于新的一天
- 跨天行为按开始时间归属

### 数据实现

**数据字段**: 
- **字段名**: date（分区字段）
- **字段类型**: date
- **取值范围**: YYYY-MM-DD 格式，如 2024-01-01
- **所在表**: 几乎所有表都有（作为分区字段）

**SQL 实现** (Trino 语法):

**方式1: 直接使用 date 字段**
```sql
SELECT 
    date,  -- 日维度
    COUNT(DISTINCT user_id) as user_count
FROM 
    dwd_user_behavior
WHERE 
    date >= date_add('day', -7, current_date)
GROUP BY 
    date
ORDER BY 
    date;
```

**方式2: 从 timestamp 提取**
```sql
SELECT 
    cast(behavior_time as date) as date,  -- 提取日期
    COUNT(DISTINCT user_id) as user_count
FROM 
    dwd_user_behavior
GROUP BY 
    cast(behavior_time as date);
```

**方式3: 相对时间表达**
```sql
-- 昨天
WHERE date = date_add('day', -1, current_date)

-- 最近7天
WHERE date >= date_add('day', -6, current_date)
  AND date <= current_date
```

### 使用场景

**适合的分析场景**:
- 日常运营监控（每日数据）
- 趋势分析（观察每日变化）
- 同比/环比分析（与昨天、去年同期对比）
- 异常检测（发现某天的异常波动）

**典型需求**:
- "查询昨天的 DAU"
- "最近 7 天的新增用户趋势"
- "每天的发帖数变化"

**与其他维度组合**:
- 日 + 渠道 → 每日各渠道的数据
- 日 + 新老用户 → 每日新老用户的对比
- 日 + 内容类型 → 每日各类型内容的数据

### 注意事项

**数据质量**:
- T+1 更新：当天的数据可能不完整
- 跨天行为：按开始时间归属
- 时区问题：确认使用的时区

**边界情况**:
- 闰年的 2 月 29 日
- 月末日期（28/29/30/31）
- 跨年的第一天和最后一天

**性能考虑**:
- date 是分区字段，必须在 WHERE 中使用
- 日期范围不要太大（明细表建议 <= 30 天）

### 示例说明

**示例1**: 查询某一天的数据
```
需求: "查询 2024-01-01 的 DAU"

SQL:
SELECT 
    date,
    COUNT(DISTINCT user_id) as dau
FROM 
    dws_user_daily
WHERE 
    date = date '2024-01-01'  -- 使用日维度筛选
GROUP BY 
    date;

结果: 2024-01-01 当天的活跃用户数
```

**示例2**: 按日聚合趋势
```
需求: "最近 7 天的 DAU 趋势"

SQL:
SELECT 
    date,  -- 日维度作为分组
    COUNT(DISTINCT user_id) as dau
FROM 
    dws_user_daily
WHERE 
    date >= date_add('day', -6, current_date)
    AND date <= current_date
GROUP BY 
    date  -- 按日分组
ORDER BY 
    date;

结果: 7 行数据，每行是一天的 DAU
```

### 示例 2: 用户维度 - 新老用户

```markdown
## 新老用户

### 基本信息

**维度名称**: 新老用户

**英文名称**: New vs Old Users

**维度类型**: 用户维度

**别名**: 
- 新老用户分层
- 用户新鲜度
- 新老区分

### 定义

**标准定义**: 
按用户注册时间距今的天数，将用户划分为新用户和老用户。

**业务含义**: 
新老用户维度用于对比不同生命周期用户的行为差异，评估产品对新老用户的吸引力。

**引用的术语**: 
- [新增用户](../glossary.md#新增用户) - 新用户的定义基础
- [用户](../glossary.md#用户) - 统计对象

### 分类规则

**分类方式**: 按注册时间距今的天数分类

**类别列表**: 

| 类别名称 | 判断条件 | 说明 | 示例 |
|---------|---------|------|------|
| 新用户 | date_diff('day', register_date, current_date) <= 30 | 注册30天内 | 注册20天的用户 |
| 老用户 | date_diff('day', register_date, current_date) > 30 | 注册超过30天 | 注册100天的用户 |

**分类特性**:
- **互斥性**: ✅ 是（一个用户只能是新用户或老用户）
- **穷尽性**: ✅ 是（所有有注册时间的用户都能分类）
- **默认值**: 如果 register_date 为 NULL，归为"未知"

**边界处理**:
- 注册时间 = 30天：算新用户（<= 30天）
- 注册时间 = 30.1天：算老用户（> 30天）
- 注册时间为 NULL：归为"未知"类别（通常排除）

**阈值说明**:
- 30天是业务定义的阈值
- 可以根据业务需求调整（如 7天、60天）
- 修改阈值会影响所有使用这个维度的分析

### 数据实现

**数据字段**: 
- **字段名**: register_date（注册日期）
- **字段类型**: date
- **取值范围**: YYYY-MM-DD 格式
- **所在表**: dwd_user_register, dws_user_daily

**SQL 实现** (Trino 语法):

**方式1: 实时计算**
```sql
SELECT 
    CASE 
        WHEN date_diff('day', register_date, current_date) <= 30 
        THEN '新用户'
        ELSE '老用户'
    END as user_type,
    COUNT(DISTINCT user_id) as user_count
FROM 
    dwd_user_register
GROUP BY 
    user_type;
```

**方式2: 使用预计算字段**（如果表中已有）
```sql
SELECT 
    user_type,  -- 假设表中已有 user_type 字段
    COUNT(DISTINCT user_id) as user_count
FROM 
    dws_user_daily
WHERE 
    date = current_date
GROUP BY 
    user_type;
```

**方式3: 在 WHERE 中筛选**
```sql
-- 只查询新用户
WHERE date_diff('day', register_date, current_date) <= 30

-- 只查询老用户
WHERE date_diff('day', register_date, current_date) > 30
```

### 使用场景

**适合的分析场景**:
- 新老用户行为对比（活跃度、留存率、付费率）
- 产品功能效果评估（新功能对新老用户的影响）
- 运营策略制定（针对新老用户的差异化运营）

**典型需求**:
- "新用户和老用户的活跃度对比"
- "各渠道的新老用户分布"
- "新用户的 7 日留存率"

**与其他维度组合**:
- 新老用户 + 日期 → 每日新老用户的活跃趋势
- 新老用户 + 渠道 → 各渠道的新老用户分布
- 新老用户 + 内容类型 → 新老用户的内容偏好

### 注意事项

**数据质量**:
- register_date 不能为 NULL
- 注册时间要准确（不是首次登录时间）

**边界情况**:
- 用户从新用户变成老用户是动态的（每天都在变化）
- 同一个用户，今天是新用户，31天后是老用户

**性能考虑**:
- 实时计算有性能开销
- 建议在汇总表中预计算 user_type 字段

### 示例说明

**示例1**: 新老用户活跃度对比
```
需求: "对比新老用户的活跃度"

SQL:
SELECT 
    CASE 
        WHEN date_diff('day', r.register_date, current_date) <= 30 
        THEN '新用户'
        ELSE '老用户'
    END as user_type,
    COUNT(DISTINCT d.user_id) as active_users
FROM 
    dws_user_daily d
JOIN 
    dwd_user_register r
ON 
    d.user_id = r.user_id
WHERE 
    d.date = current_date
    AND d.is_active = 1
GROUP BY 
    user_type;

结果: 
新用户: 50万
老用户: 100万
```

## ⚠️ 常见错误

### 错误 1: 分类不互斥

❌ 错误示例:
```markdown
| 类别 | 条件 |
|------|------|
| 新用户 | 注册 <= 30天 |
| 活跃用户 | 有行为记录 |
```
**问题**: 一个用户可能既是新用户又是活跃用户（不互斥）

✅ 正确示例:
```markdown
这是两个不同的维度，不应该放在一起：
- 维度1: 新老用户（新/老）
- 维度2: 活跃状态（活跃/不活跃）
```

### 错误 2: 分类不穷尽

❌ 错误示例:
```markdown
| 类别 | 条件 |
|------|------|
| 新用户 | 注册 < 30天 |
| 老用户 | 注册 > 30天 |
```
**问题**: 注册 = 30天的用户没有归属

✅ 正确示例:
```markdown
| 类别 | 条件 |
|------|------|
| 新用户 | 注册 <= 30天 |
| 老用户 | 注册 > 30天 |
```

### 错误 3: 缺少 SQL 实现

❌ 错误示例:
```markdown
只有定义，没有 SQL 实现
```
**问题**: AI 不知道如何在 SQL 中使用这个维度

✅ 正确示例:
```markdown
提供完整的 SQL 实现示例（Trino 语法）
```

### 错误 4: 边界不明确

❌ 错误示例:
```markdown
新用户: 注册时间比较短的用户
```
**问题**: "比较短"是多短？没有明确标准

✅ 正确示例:
```markdown
新用户: 注册时间 <= 30天
边界: 注册 = 30天算新用户
```
