# 业务知识模板使用指南

> 如何使用四类标准模板创建高质量的业务知识

---

## 🎯 四类模板

| 模板 | 用途 | 何时使用 |
|------|------|---------|
| [GLOSSARY_TEMPLATE.md](GLOSSARY_TEMPLATE.md) | 定义业务术语 | 需要定义基础概念（名词） |
| [dimensions/DIMENSION_TEMPLATE.md](dimensions/DIMENSION_TEMPLATE.md) | 定义维度 | 需要定义分析角度（分类） |
| [metrics/METRIC_TEMPLATE.md](metrics/METRIC_TEMPLATE.md) | 定义指标 | 需要定义业务度量（数值） |
| [calculation_rules/CALCULATION_TEMPLATE.md](calculation_rules/CALCULATION_TEMPLATE.md) | 定义计算规则 | 指标计算复杂（多表、多步骤） |

## 🔍 如何判断使用哪个模板？

### 决策树

```
我要添加的内容是什么？
    |
    ├─ 基础概念（名词）
    |   → 术语模板
    |   → 例: "活跃用户"、"帖子"
    |
    ├─ 分类/角度
    |   → 维度模板
    |   → 例: "新老用户"、"内容类型"
    |
    ├─ 可量化的度量
    |   ├─ 简单（单表、<20行）
    |   |   → 指标模板
    |   |   → 例: "DAU"、"发帖数"
    |   |
    |   └─ 复杂（多表、>30行）
    |       → 指标模板 + 计算规则模板
    |       → 例: "次日留存率"
    |
    └─ 复杂计算方法
        → 计算规则模板
        → 例: "留存率计算"
```

### 常见混淆

| 容易混淆 | 正确分类 | 判断依据 |
|---------|---------|---------|
| "日活" | 指标（DAU） | 可量化，有数值 |
| "活跃" | 术语（活跃用户） | 基础概念 |
| "新用户" | 术语 + 维度 | 既是概念，也是分类 |
| "新增用户数" | 指标 | 可量化 |

## 🎓 核心概念

### 1. 什么是"口径"？⭐最重要

**定义**：统计数据时的具体规则和边界

**为什么重要**：
```
同一名称，不同口径，结果完全不同：

"活跃用户"
- 只统计登录 → 100万
- 统计所有行为 → 150万
- 只统计发帖 → 10万
```

**必须明确5个要素**：
1. 统计对象（user_id、post_id）
2. 去重规则（按什么去重）
3. 时间范围（如何界定时间）
4. 包含条件（什么算）
5. 排除条件（什么不算）

### 2. 什么是"分类规则"？

**定义**：如何将数据划分到不同类别

**必须明确4个特性**：
1. **互斥性** - 一个数据只能属于一个类别
2. **穷尽性** - 所有数据都能分类
3. **边界明确** - 边界值的归属清晰
4. **默认值** - 无法判断时的处理

**示例**：
```
新老用户:
- 新用户: 注册 <= 30天
- 老用户: 注册 > 30天
- 互斥: ✅ 是
- 穷尽: ✅ 是
- 边界: 30天算新用户
- 默认: NULL归"未知"
```

### 3. 什么是"引用关系"？

**定义**：知识之间的依赖和关联

**为什么重要**：
- 保证口径一致
- 可追溯知识来源
- 便于维护

**如何标注**：
```markdown
**引用的术语**: [活跃用户](../glossary.md#活跃用户)
**引用的维度**: [日](../dimensions/time_dimensions.md#日)
```

## 📝 填写顺序

```
1. 术语表 → 定义基础概念
2. 维度定义 → 定义分析角度
3. 指标定义 → 组合术语和维度
4. 计算规则 → 提供复杂实现
```

**为什么这个顺序**：
- 术语是基础，被所有人引用
- 维度引用术语
- 指标引用术语和维度
- 计算规则引用所有

---

## 💡 填写技巧

### 1. 口径要详尽
- ❌ "统计活跃用户"
- ✅ 明确5个要素（统计对象、去重、时间、包含、排除）

### 2. 示例要具体
- ❌ "活跃用户是有行为的用户"
- ✅ "用户A登录→算活跃；用户B只收到推送→不算"

### 3. 关联要明确
- ❌ "DAU是日活跃用户数"
- ✅ 引用[活跃用户]、引用[日]

### 4. 错误要说后果
- ❌ "不要用 INNER JOIN"
- ✅ "用 INNER JOIN 会遗漏未留存用户，留存率虚高（30%→100%）"

## ✅ 质量检查

**术语**:
- [ ] 定义一句话说清？
- [ ] 口径5要素齐全？
- [ ] 别名>=2个？
- [ ] 示例>=2个？

**维度**:
- [ ] 分类互斥？
- [ ] 分类穷尽？
- [ ] 边界明确？
- [ ] SQL完整？

**指标**:
- [ ] 引用关系明确？
- [ ] 口径完整？
- [ ] 简单指标有SQL？
- [ ] 复杂指标引用计算规则？

**计算规则**:
- [ ] 步骤完整？
- [ ] SQL可执行？
- [ ] 关键点说"为什么"？
- [ ] 错误说"后果"？
