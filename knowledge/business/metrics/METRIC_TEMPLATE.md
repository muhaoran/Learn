# 指标定义模板

> 指标是可量化的业务度量，组合术语和维度形成完整表达

---

## 📋 什么是指标？

- ✅ 可量化的度量（如"DAU"、"次日留存率"）
- ❌ 不是术语（术语是概念）
- ❌ 不是维度（维度是角度）

**指标 = 术语 + 维度 + 聚合方式**
```
例: DAU = 活跃用户（术语）+ 日（维度）+ 数量（COUNT）
```

---

## 📝 标准模板

```markdown
## [指标名称]

**指标名称**: [正式名称]

**英文/缩写**: [如 Daily Active User / DAU]

**指标类型**: [基础指标/复合指标/比率指标]

**别名**: [别名1]、[别名2]

**定义**: 
[用一句话清晰定义这个指标]

**计算公式**: 
```
[指标] = [计算公式]

其中:
- [变量1]: [说明]
- [变量2]: [说明]
```

**引用关系**: ⭐核心

> 指标通过组合术语和维度形成，必须明确引用关系

- **引用的术语**: [术语1](../glossary.md#术语1)
- **引用的维度**: [维度1](../dimensions/xxx.md#维度1)
- **引用的指标**: [指标1](xxx.md#指标1) (如果是复合指标)

**数据口径**: ⭐核心

> 口径决定了指标的数值

- **统计对象**: [如 user_id]
- **聚合方式**: [如 COUNT(DISTINCT)]
- **去重规则**: [如 按 user_id 去重]
- **时间粒度**: [如 日]
- **时间范围**: [如 自然日 00:00-23:59]
- **包含条件**: [什么算]
- **排除条件**: [什么不算]

**数据来源**:
- **推荐表**: [表名] - [选择理由：性能好/数据完整]
- **备选表**: [表名] - [使用场景：需要自定义时]

**计算规则**:

**简单指标** (直接写 SQL):
```sql
SELECT 
    [维度],
    [聚合函数] as [指标]
FROM [表]
WHERE [条件]
GROUP BY [维度];
```

**复杂指标** (引用计算规则):
- 详见: [calculation_rules/xxx.md](../calculation_rules/xxx.md)
- 关键点: [列出关键技术点]

**使用场景**:
- ✅ [适合场景]
- ❌ [不适合场景]

**解读说明**:
- 正常范围: [数值范围]
- 数值上升: [代表什么]
- 数值下降: [代表什么]

**相关指标**: [指标1]、[指标2]

**维护信息**:
- 负责人: [xxx]
- 更新时间: [YYYY-MM-DD]
```

## 🔑 核心说明

### ⭐ 数据口径（最重要）

**必须明确7个要素**：
1. **统计对象**: user_id、post_id
2. **聚合方式**: COUNT、SUM、AVG、比率
3. **去重规则**: 按什么去重
4. **时间粒度**: 日、周、月
5. **时间范围**: 如何界定时间
6. **包含条件**: 什么算
7. **排除条件**: 什么不算

### 引用关系

**为什么重要**：
- 保证口径一致（引用统一的定义）
- 可追溯（知道知识来源）
- 便于维护（术语变化时知道影响）

**如何标注**：
```markdown
**引用的术语**: [活跃用户](../glossary.md#活跃用户)
**引用的维度**: [日](../dimensions/time_dimensions.md#日)
```

### 简单指标 vs 复杂指标

| 类型 | 特征 | 处理方式 |
|------|------|---------|
| 简单 | 单表、简单聚合、SQL<20行 | 直接写 SQL |
| 复杂 | 多表、复杂逻辑、SQL>30行 | 引用 calculation_rules/ |

## 📊 完整示例

### 示例1: 简单指标 - DAU

```markdown
## DAU (日活跃用户数)

**指标名称**: 日活跃用户数

**英文/缩写**: Daily Active User / DAU

**指标类型**: 基础指标

**别名**: 日活、日活用户

**定义**: 
某自然日内有任意行为的去重用户数。

**计算公式**: 
```
DAU = COUNT(DISTINCT user_id)
WHERE 行为日期 = 统计日期 AND 符合活跃定义
```

**引用关系**:
- **引用的术语**: [活跃用户](../glossary.md#活跃用户)
- **引用的维度**: [日](../dimensions/time_dimensions.md#日)

**数据口径**:
- **统计对象**: user_id
- **聚合方式**: COUNT(DISTINCT)
- **去重规则**: 按 user_id 去重
- **时间粒度**: 日
- **时间范围**: 自然日 00:00-23:59，按行为发生时间
- **包含条件**: 行为类型 IN (登录, 浏览, 发帖...)
- **排除条件**: 排除测试账号

**数据来源**:
- **推荐表**: dws_user_daily - 汇总表，速度快
- **备选表**: dwd_user_behavior - 明细表，灵活性高

**计算规则** (简单指标):
```sql
SELECT 
    date,
    COUNT(DISTINCT user_id) as dau
FROM dws_user_daily
WHERE date = date_add('day', -1, current_date)
  AND is_active = 1
GROUP BY date;
```

**使用场景**:
- ✅ 日常监控、趋势分析
- ❌ 实时监控（T+1更新）

**解读说明**:
- 正常范围: 100-200万
- 数值上升: 用户活跃度提升
- 数值下降: 需要分析原因

**相关指标**: WAU、MAU、活跃率

**维护信息**:
- 负责人: 数据部门
- 更新时间: 2024-01-01
```

### 示例2: 复杂指标 - 次日留存率

```markdown
## 次日留存率

**指标名称**: 次日留存率

**英文/缩写**: Day 1 Retention Rate / D1 RR

**指标类型**: 比率指标

**别名**: 次留、D1留存

**定义**: 
某日新增的用户中，在次日（D1）仍然活跃的用户占比。

**计算公式**: 
```
次日留存率 = (D1活跃用户数 / D0新增用户数) × 100%

其中:
- D0: 注册日
- D1: 注册日 + 1天
```

**引用关系**:
- **引用的术语**: [新增用户](../glossary.md#新增用户)、[活跃用户](../glossary.md#活跃用户)
- **引用的维度**: [日](../dimensions/time_dimensions.md#日)

**数据口径**:
- **统计对象**: user_id
- **聚合方式**: 比率（分子/分母×100%）
- **去重规则**: 分子分母都按 user_id 去重
- **时间粒度**: 日
- **时间范围**: D0注册日，D1=D0+1天
- **包含条件**: D0注册成功，D1有活跃行为
- **排除条件**: 排除测试账号

**数据来源**:
- **表1**: dwd_user_register（D0新增）
- **表2**: dwd_user_behavior（D1活跃）
- **关联**: LEFT JOIN

**计算规则** (复杂指标):
- 详见: [retention.md](../calculation_rules/retention.md)
- 关键点: 
  - 必须用 LEFT JOIN（不能用 INNER JOIN）
  - 时间计算: date_add('day', 1, register_date)
  - 分子分母都要 DISTINCT

**使用场景**:
- ✅ 评估产品留存能力、渠道质量
- ❌ 实时监控（需等D1结束）

**解读说明**:
- 优秀: >40%
- 良好: 30-40%
- 一般: 20-30%

**相关指标**: 7日留存率、30日留存率

**维护信息**:
- 负责人: 数据部门
- 更新时间: 2024-01-01
```
