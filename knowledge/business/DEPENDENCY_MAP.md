# 业务知识依赖关系图

> 展示业务知识层四个部分之间的引用和依赖关系

---

## 📊 整体依赖关系

### 层次结构

```
┌─────────────────────────────────────────────────┐
│  第1层: 术语表 (glossary.md)                     │
│  - 活跃用户、新增用户、留存用户...               │
│  - 最基础，被所有人引用                          │
└─────────────────────────────────────────────────┘
                    ↑ 被引用
                    |
┌─────────────────────────────────────────────────┐
│  第2层: 维度定义 (dimensions/)                   │
│  - 时间维度（日/周/月）                          │
│  - 用户维度（新老/等级/渠道）                    │
│  - 引用术语，被指标引用                          │
└─────────────────────────────────────────────────┘
                    ↑ 被引用
                    |
┌─────────────────────────────────────────────────┐
│  第3层: 指标定义 (metrics/)                      │
│  - DAU、MAU、次日留存率...                       │
│  - 引用术语和维度，被计算规则引用                │
└─────────────────────────────────────────────────┘
                    ↑ 被引用
                    |
┌─────────────────────────────────────────────────┐
│  第4层: 计算规则 (calculation_rules/)            │
│  - 留存率计算、DAU/MAU 计算...                   │
│  - 引用所有，提供最终实现                        │
└─────────────────────────────────────────────────┘
```

## 🎯 使用指南

### 场景 1: 添加新指标

**步骤**：

1. **检查术语表**
   - 需要的术语是否已定义？
   - 如果没有，先添加到 glossary.md

2. **检查维度定义**
   - 需要的维度是否已定义？
   - 如果没有，先添加到 dimensions/

3. **添加指标定义**
   - 在 metrics/ 中添加指标
   - 明确引用术语和维度
   - 提供计算公式

4. **是否需要计算规则？**
   - 如果简单（如 DAU）→ 不需要
   - 如果复杂（如留存率）→ 创建 calculation_rules/

**示例**: 添加"7日留存率"

```
检查:
  ✅ 术语"留存用户"已存在
  ✅ 维度"日"已存在
  ✅ 计算规则 retention.md 已存在
  
只需要:
  在 user_metrics.md 中添加"7日留存率"定义
  引用已有的术语、维度、计算规则
```

### 场景 2: 修改术语定义

**步骤**：

1. **修改 glossary.md**
   - 更新术语定义

2. **检查影响范围**
   - 查看依赖矩阵，哪些指标引用了这个术语
   - 检查这些指标是否需要调整

3. **更新相关文档**
   - 如果指标定义需要调整，更新 metrics/
   - 如果计算规则需要调整，更新 calculation_rules/

4. **记录变更**
   - 在维护日志中记录修改
   - 说明影响范围

**示例**: 修改"活跃用户"的定义

```
修改:
  glossary.md 中"活跃用户"的行为范围
  
影响:
  - DAU 定义（引用了"活跃用户"）
  - WAU 定义（引用了"活跃用户"）
  - MAU 定义（引用了"活跃用户"）
  - 留存率定义（判断活跃时使用）
  
需要:
  检查上述指标，确认定义仍然准确
```

## 🔍 依赖检查清单

### 添加新内容时检查

**添加新术语**:
- [ ] 定义是否清晰无歧义？
- [ ] 是否列出所有别名和黑话？
- [ ] 是否与已有术语冲突？
- [ ] 是否标注相关术语？

**添加新维度**:
- [ ] 是否引用了相关术语？
- [ ] 分类规则是否清晰？
- [ ] 是否提供 SQL 实现？
- [ ] 是否说明使用场景？

**添加新指标**:
- [ ] 是否明确引用术语和维度？
- [ ] 计算公式是否清晰？
- [ ] 数据来源是否明确？
- [ ] 是否需要创建计算规则？

**添加新计算规则**:
- [ ] 是否列出引用的术语和维度？
- [ ] SQL 模板是否完整？
- [ ] 是否标注常见错误？
- [ ] 是否提供变体场景？

### 修改已有内容时检查

**修改术语**:
- [ ] 是否检查了所有引用这个术语的指标？
- [ ] 是否检查了所有引用这个术语的计算规则？
- [ ] 是否更新了相关文档？
- [ ] 是否记录了变更日志？

**修改维度**:
- [ ] 是否检查了所有使用这个维度的指标？
- [ ] SQL 实现是否需要调整？
- [ ] 是否影响已有的 SQL 案例？

**修改指标**:
- [ ] 是否影响计算规则？
- [ ] 是否影响 SQL 案例？
- [ ] 是否需要更新数据表文档？
