# Skill: 需求澄清

---

## 目标

识别需求中的模糊点和歧义，通过提问澄清，确保准确理解用户需求。

---

## 触发条件

在需求解析后，如果发现不确定项（uncertainties 不为空），触发此技能。

---

## 输入

- 需求解析的结果（包含 uncertainties）
- 用户的原始需求

---

## 处理步骤

### 步骤 1: 评估不确定项的优先级

**优先级规则**:
- **高优先级**: 影响 SQL 核心逻辑的问题
  - 指标不明确
  - 计算规则不明确
  - 时间范围不明确
  
- **中优先级**: 影响结果展示的问题
  - 维度不明确
  - 排序方式不明确
  
- **低优先级**: 可以使用默认值的问题
  - 是否需要限制结果数量
  - 是否需要小数位数

### 步骤 2: 生成澄清问题

**原则**:
- 一次不要问太多问题（最多 3-5 个）
- 提供选项而非开放式问题
- 说明不同选项的差异
- 给出推荐选项（如果有）

**问题模板**:

#### 模板 1: 二选一
```
关于 [问题项]，请确认：
A. [选项 A] - [说明]
B. [选项 B] - [说明]

推荐: [推荐选项]（[推荐理由]）
```

#### 模板 2: 多选一
```
关于 [问题项]，请选择：
1. [选项 1] - [说明]
2. [选项 2] - [说明]
3. [选项 3] - [说明]
```

#### 模板 3: 补充信息
```
请补充以下信息：
- [信息项 1]: [说明为什么需要]
- [信息项 2]: [说明为什么需要]
```

### 步骤 3: 组织澄清消息

**结构**:
```markdown
## 需求理解

[用标准术语复述已理解的部分]

## 需要确认

[列出澄清问题]

## 补充说明

[如果有必要，说明为什么需要澄清这些问题]
```

### 步骤 4: 等待用户回复

用户回复后，更新需求信息，继续下一步。

---

## 输出

澄清问题列表，发送给用户。

---

## 示例

### 示例 1: 时间范围不明确

**输入**:
```json
{
  "metrics": ["DAU"],
  "time_range": {"type": "relative", "value": "last_week"},
  "uncertainties": [
    {
      "item": "时间范围",
      "issue": "最近一周 不明确",
      "options": ["最近7天", "上周(周一到周日)"]
    }
  ]
}
```

**输出**:
```markdown
## 需求理解

您想查询 DAU（日活跃用户数）。

## 需要确认

关于时间范围，请确认"最近一周"是指：
A. 最近 7 天（含今天）
B. 上周（上周一到上周日）

推荐: A（最近 7 天更常用）
```

### 示例 2: 指标不明确

**输入**:
```json
{
  "metrics": [],
  "uncertainties": [
    {
      "item": "指标",
      "issue": "用户情况 过于模糊",
      "options": ["DAU", "新增用户数", "活跃率", "留存率"]
    }
  ]
}
```

**输出**:
```markdown
## 需求理解

您想查询用户相关的数据。

## 需要确认

"用户情况" 比较宽泛，请问您具体想看：
1. 活跃用户数（DAU/WAU/MAU）
2. 新增用户数
3. 活跃率（活跃用户 / 总用户）
4. 留存率（次日留存、7日留存等）
5. 其他（请说明）

或者您可以直接描述想要分析什么问题，我来帮您确定合适的指标。
```

### 示例 3: 多个不确定项

**输入**:
```json
{
  "metrics": ["次日留存率"],
  "dimensions": ["channel"],
  "time_range": {"type": "relative", "value": "last_month"},
  "uncertainties": [
    {
      "item": "时间范围",
      "issue": "最近一个月 不明确",
      "options": ["最近30天", "本自然月", "上个自然月"]
    },
    {
      "item": "维度",
      "issue": "渠道 不明确",
      "options": ["注册渠道", "活跃渠道"]
    }
  ]
}
```

**输出**:
```markdown
## 需求理解

您想查询新用户的次日留存率，按渠道分组。

## 需要确认

请确认以下几点：

1. **时间范围** - "最近一个月" 是指：
   A. 最近 30 天（如今天是 2月15日，则为 1月16日-2月15日）
   B. 本自然月（2月1日-2月15日）
   C. 上个自然月（1月1日-1月31日）
   
   推荐: C（上个自然月），因为可以看到完整月份的数据

2. **渠道维度** - "按渠道分" 是指：
   A. 按注册渠道分组（用户是从哪个渠道注册的）
   B. 按活跃渠道分组（用户在哪个平台活跃）
   
   推荐: A（注册渠道），因为留存分析通常看注册渠道质量
```

## 注意事项

### 1. 避免过度提问

**不好的做法**:
```
请确认：
1. 时间范围？
2. 是否包含今天？
3. 是否需要去重？
4. 是否需要排序？
5. 是否需要限制结果数量？
6. 是否需要保留小数？
7. ...
```

**好的做法**:
```
请确认时间范围：
A. 最近 7 天（含今天）
B. 过去 7 个完整的自然日（不含今天）

其他细节（去重、排序等）我会按照标准规范处理。
```

### 2. 提供上下文

说明为什么需要澄清，帮助用户理解。

**示例**:
```
关于"渠道"，需要确认是注册渠道还是活跃渠道，因为：
- 注册渠道: 反映用户来源质量
- 活跃渠道: 反映用户使用习惯
两者的分析意义不同。
```

### 3. 给出推荐

如果有明显的最佳实践，给出推荐。

**示例**:
```
推荐: 使用"最近 30 天"，因为：
- 数据完整（不受月份天数影响）
- 更符合运营习惯
```

### 4. 允许用户跳过

对于低优先级的问题，可以使用默认值。

**示例**:
```
如果不需要特别指定，我将使用以下默认设置：
- 结果按日期升序排列
- 保留 2 位小数
- 不限制结果数量
```

## 澄清策略

### 策略 1: 渐进式澄清

对于复杂需求，分多轮澄清：
- 第一轮: 澄清核心问题（指标、时间）
- 第二轮: 澄清细节问题（维度、筛选）

### 策略 2: 假设验证

对于有明显默认理解的需求，先给出假设，让用户确认：

```markdown
我理解您的需求是：[假设的理解]

如果理解有误，请指正。
```

### 策略 3: 提供示例

通过示例帮助用户理解选项差异：

```markdown
关于时间范围：
A. 最近 7 天（含今天）: 2024-01-09 到 2024-01-15
B. 过去 7 天（不含今天）: 2024-01-08 到 2024-01-14

请选择。
```

## 特殊场景

### 场景 1: 用户使用了错误的术语

**示例**: 用户说"查询 DAU 的留存率"（DAU 和留存率是两个不同的指标）

**处理**:
1. 礼貌地指出可能的混淆
2. 询问真实意图
3. 提供正确的表达方式

### 场景 2: 需求自相矛盾

**示例**: "查询新用户的 MAU"（新用户通常按日分析，MAU 是月度指标）

**处理**:
1. 指出矛盾点
2. 询问真实意图
3. 提供合理的替代方案

---

## 成功标准

- ✅ 所有高优先级不确定项都得到澄清
- ✅ 用户确认理解正确
- ✅ 没有遗漏关键问题
- ✅ 没有过度提问
