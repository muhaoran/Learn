# 反馈收集

> 记录 ChatBI 使用过程中发现的问题和知识缺口，用于持续改进知识库。

---

## 目录结构

```
feedback/
├── corrections/          # SQL 纠错记录（AI 生成有误的情况）
├── knowledge_gaps/       # 知识缺口记录（知识库缺失的情况）
└── new_cases/            # 新需求类型记录（可沉淀为指标/模式的新案例）
```

---

## 反馈类型

### corrections/ — SQL 纠错

**触发时机**：AI 生成的 SQL 不准确，需要人工修正。

记录内容：原始需求、错误 SQL、正确 SQL、错误原因、知识库更新建议。

**后续动作**：根据错误原因更新对应的知识库文件（schema/semantics/patterns/metrics）。

### knowledge_gaps/ — 知识缺口

**触发时机**：AI 明确告知知识库中缺少某个定义，或用户提出了知识库无法覆盖的需求。

记录内容：缺失的知识类型、具体内容、触发需求、补充优先级。

**后续动作**：将缺失的知识整理后写入 `knowledge/` 对应层（或放入 `raw_knowledge/mixed/` 由 AI 处理）。

### new_cases/ — 新需求类型

**触发时机**：出现了知识库未覆盖、但 AI 已基于现有信息生成并验证正确的新需求；预期未来还会复用。

记录内容：原始需求、最终 SQL、为什么是"新"需求、可复用结构分析、沉淀建议。

**后续动作**：分析 SQL 中可复用的结构，按建议沉淀到对应层——
- 新计算结构 → `knowledge/patterns/`
- 新指标 → `knowledge/metrics/`
- 新业务概念 → `knowledge/semantics/`
- 新表/字段 → `knowledge/schema/tables/`

## 模板统一骨架

三类模板共享同一套字段结构，便于检索、统计和后续工具化：

```
# {标题}

- 日期 / 领域分类字段 / 优先级 / 状态     ← 元信息头部

## 原始需求                                ← 全部统一
## {领域内容}                              ← 各模板特有
   - corrections: AI 错误 SQL + 问题描述 + 正确 SQL
   - knowledge_gaps: 缺失内容描述
   - new_cases: 最终 SQL + 为什么是"新" + 复用结构分析
## {分类清单}（checkbox）                  ← 根因 / 缺失类型 / 沉淀建议
## 后续计划                                ← 负责人 / 计划完成 / 关联文件 / 临时处理
## 完成情况（checkbox）
```

新增模板时请遵循此骨架。

---

## 使用说明

**AI 自动记录**：发现知识缺口或 SQL 不准确时，AI 会在对话中提示，并建议记录到对应目录。

**人工记录**：
1. 复制对应目录下的模板文件
2. 按模板填写（命名建议：`YYYY-MM-DD_描述.md`）
3. 根据"分类清单"和"后续计划"更新知识库
