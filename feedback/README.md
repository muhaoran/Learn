# 反馈收集系统

> 本目录用于收集 ChatBI 使用过程中的反馈，用于持续改进。

---

## 目录结构

```
feedback/
├── corrections/         # SQL 纠错记录
├── new_cases/          # 新案例收集
├── knowledge_gaps/     # 知识缺口
└── improvements/       # 改进建议
```

---

## 反馈类型

### 1. SQL 纠错 (`corrections/`)

**场景**: 生成的 SQL 不准确，用户进行了修改。

**记录内容**:
- 原始需求
- AI 生成的 SQL
- 问题描述
- 正确的 SQL
- 错误原因分析

**用途**:
- 分析错误模式
- 更新知识库
- 优化生成逻辑

### 2. 新案例 (`new_cases/`)

**场景**: 新的需求类型，值得加入案例库。

**记录内容**:
- 需求描述
- 生成的 SQL
- 技术方案
- 注意事项

**用途**:
- 丰富 SQL 案例库
- 扩展系统能力

### 3. 知识缺口 (`knowledge_gaps/`)

**场景**: 知识库中缺少某些信息。

**记录内容**:
- 缺失的知识类型（术语、指标、表、案例）
- 具体缺失内容
- 影响范围
- 优先级

**用途**:
- 识别知识库的不足
- 指导知识库建设
- 优先级排序

### 4. 改进建议 (`improvements/`)

**场景**: 系统使用过程中的改进建议。

**记录内容**:
- 建议内容
- 改进理由
- 预期效果

**用途**:
- 优化系统流程
- 提升用户体验

---

## 反馈收集流程

### 自动收集

每次交互后，AI 自动记录：
1. 需求和生成的 SQL
2. 是否需要澄清
3. 是否有知识缺口
4. 用户是否满意（如果有反馈）

### 人工反馈

用户可以主动提供反馈：
1. SQL 不准确
2. 理解有偏差
3. 澄清问题不合理
4. 其他建议

---

## 反馈处理流程

```
收集反馈
    ↓
分类整理
    ↓
优先级评估
    ↓
制定改进方案
    ↓
更新知识库/优化系统
    ↓
验证效果
```

---

## 反馈分析

### 定期分析（建议每周）

1. **统计数据**:
   - SQL 准确率
   - 需求理解准确率
   - 澄清问题有效性
   - 知识缺口数量

2. **错误分析**:
   - 错误类型分布
   - 高频错误
   - 根因分析

3. **改进计划**:
   - 知识库补充计划
   - 系统优化计划
   - 优先级排序

## 使用说明

### For AI

每次交互后，检查是否需要记录反馈：

```python
# 伪代码
if sql_generated:
    if user_corrected:
        record_to("feedback/corrections/")
    if is_new_case_type:
        record_to("feedback/new_cases/")
    if knowledge_missing:
        record_to("feedback/knowledge_gaps/")
```

### For Human

1. **提供反馈**: 
   - 如果 SQL 不准确，请说明问题
   - 如果有新的业务概念，请提供定义
   - 如果有改进建议，请告知

2. **定期 Review**:
   - 每周查看反馈记录
   - 分析问题原因
   - 更新知识库
