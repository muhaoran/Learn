# 快速开始指南

## 第一次使用

### 1. 准备知识库

在开始使用 ChatBI 之前，需要先构建知识库：

#### 必需的知识（高优先级）:
- [ ] 业务术语表（至少 20 个核心术语）
- [ ] 核心指标定义（至少 10 个常用指标）
- [ ] 数据表结构（至少 10 张核心表）
- [ ] SQL 案例（至少 10 个典型案例）

#### 建议的知识（中优先级）:
- [ ] 表关联关系图
- [ ] 计算规则文档
- [ ] 数据质量说明
- [ ] SQL 最佳实践

### 2. 填充知识库

参考 `knowledge/` 目录下的模板文件，填充你的业务信息。

### 3. 测试验证

使用 `tests/test_cases.md` 中的测试用例验证效果。

## 使用方式

### 方式 1: 通过 Cursor Chat

在 Cursor 中与 AI 对话：

```
用户: 查询昨天的 DAU，按渠道分

AI: [自动读取知识库，生成 SQL]
```

### 方式 2: 通过 Cloud Agent

创建 GitHub Issue，触发 Cloud Agent 自动处理。

## 示例对话

### 示例 1: 简单查询

**用户**: 
```
查询最近 7 天的 DAU 趋势
```

**AI**:
```
我理解您的需求是：查询过去 7 天（含今天）每天的活跃用户数。

根据雪球的 DAU 定义（有任意行为的去重用户），SQL 如下：

[SQL 代码]

说明：
- 使用了 dws_user_daily 汇总表
- 已按 user_id 去重
- 时间范围: [开始日期] 至 [结束日期]
```

### 示例 2: 需要澄清的查询

**用户**:
```
帮我看下新用户的留存情况
```

**AI**:
```
您好，关于"新用户的留存情况"，我需要确认几个细节：

1. 时间范围：您想看哪个时间段注册的新用户？（如最近 30 天、本月、本季度）
2. 留存类型：次日留存、7 日留存、还是 30 日留存？
3. 维度：需要按什么维度分组吗？（如渠道、用户类型等）

请补充这些信息，我将为您生成准确的 SQL。
```

### 示例 3: 复杂查询

**用户**:
```
分析一下 Q1 通过广告渠道来的用户，他们的发帖行为和留存表现
```

**AI**:
```
我理解您的需求涉及多个维度的分析。让我确认一下：

需求拆解：
1. 用户范围：Q1（1-3月）注册的广告渠道用户
2. 分析内容：
   - 发帖行为（发帖数、发帖用户数、人均发帖数？）
   - 留存表现（次日留存？7日留存？30日留存？）
3. 分析粒度：按月？按渠道细分？还是整体？

请确认或补充细节。
```

## 最佳实践

### 提需求时的建议

**好的需求描述**:
- ✅ "查询 2024 年 1 月新注册用户的次日留存率，按渠道分组"
- ✅ "统计最近 30 天每天的 DAU 和 MAU"
- ✅ "分析 VIP 用户在最近一周的发帖数和点赞数"

**不够清晰的需求**:
- ❌ "看下用户情况" （太模糊）
- ❌ "统计留存" （缺少时间范围、留存类型）
- ❌ "分析活跃度" （指标不明确）

### 如何获得更好的结果

1. **提供上下文**: 说明分析目的，帮助 AI 理解意图
2. **使用标准术语**: 参考业务术语表
3. **明确时间范围**: 具体到日期或相对时间
4. **说明特殊要求**: 如性能要求、数据精度要求

## 反馈机制

### 如果 SQL 不准确

请提供以下信息：
1. 原始需求
2. AI 生成的 SQL
3. 问题描述（哪里不对）
4. 正确的 SQL（如果有）

我们会：
1. 分析问题原因
2. 更新知识库
3. 优化生成逻辑

### 如果遇到新的业务概念

请提供：
1. 术语名称
2. 业务定义
3. 计算规则
4. 示例

我们会将其加入知识库。

## 常见问题

### Q: AI 能处理多复杂的需求？

A: 理论上可以处理任意复杂度的需求，但复杂需求可能需要多轮澄清。建议将特别复杂的需求拆分成多个子需求。

### Q: 如果知识库中没有相关信息怎么办？

A: AI 会明确告知缺少哪些信息，并请求补充。你可以临时提供信息，或者更新知识库。

### Q: 生成的 SQL 可以直接执行吗？

A: 建议先在测试环境验证，确认结果正确后再在生产环境使用。

### Q: 如何提高准确率？

A: 
1. 丰富知识库（更多案例、更详细的定义）
2. 提供准确的需求描述
3. 及时反馈错误，帮助系统学习
