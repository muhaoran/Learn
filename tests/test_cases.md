> 本文档包含用于测试 ChatBI 系统的测试用例。

## 测试目标

验证 ChatBI 系统能够：
1. 正确理解各类需求

4. 符合业务定义和数据口径

## 基础查询测试用例

### 用例 1.1: 查询单日 DAU

**需求描述**:
```
查询昨天的 DAU
```

**预期行为**:
- ✅ 正确识别指标: DAU
- ✅ 正确识别时间: 昨天
- ✅ 无需澄清（需求明确）
- ✅ 使用 `dws_user_daily` 表
- ✅ 正确的时间条件: `date = DATE_SUB(CURRENT_DATE(), INTERVAL 1 DAY)`

**预期 SQL 结构**:
```sql
SELECT 
    date,
    COUNT(DISTINCT user_id) as dau
FROM 
    dws_user_daily
WHERE 
    date = DATE_SUB(CURRENT_DATE(), INTERVAL 1 DAY)
    AND is_active = 1
GROUP BY 
    date;
```

**评分标准**:
- SQL 语法正确: 2 分
- 使用正确的表: 2 分
- 时间条件正确: 2 分
- 符合 DAU 定义: 2 分
- 有清晰注释: 2 分
- **总分**: 10 分

### 用例 1.2: 查询时间范围的 DAU

**需求描述**:
```
查询最近 7 天的 DAU 趋势
```

**预期行为**:
- ✅ 识别指标: DAU
- ✅ 识别时间: 最近 7 天
- ✅ 识别维度: 日期（按日展示）
- ⚠️ 可能需要澄清: 是否包含今天（建议默认包含）

**预期 SQL 结构**:
```sql
SELECT 
    date,
    COUNT(DISTINCT user_id) as dau
FROM 
    dws_user_daily
WHERE 
    date >= DATE_SUB(CURRENT_DATE(), INTERVAL 6 DAY)
    AND date <= CURRENT_DATE()
    AND is_active = 1
GROUP BY 
    date
ORDER BY 
    date;
```

## 高复杂度测试用例

### 用例 3.1: 次日留存率

**需求描述**:
```
计算 1 月份新用户的次日留存率，按注册渠道分组
```

**预期行为**:
- ✅ 识别复杂指标: 次日留存率
- ✅ 正确理解计算规则
- ✅ 使用 CTE 结构
- ✅ 使用 LEFT JOIN
- ✅ 时间计算正确（D1 = D0 + 1）

**预期 SQL 结构**:
```sql
WITH new_users AS (...),
retention_users AS (...)
SELECT 
    ...,
    COUNT(DISTINCT nu.user_id) as new_users_count,
    COUNT(DISTINCT ru.user_id) as retention_users_count,
    ROUND(...) as retention_rate
FROM new_users nu
LEFT JOIN retention_users ru ON ...
```

## 边界情况测试用例

### 用例 4.1: 模糊需求

**需求描述**:
```
看下用户情况
```

**预期行为**:
- ✅ 识别需求过于模糊
- ✅ 主动询问具体想看什么指标
- ✅ 提供常见选项（DAU、新增、留存等）
- ❌ 不能直接猜测并生成 SQL

---

### 用例 4.2: 黑话翻译

**需求描述**:
```
帮我看下最近的次留
```

**预期行为**:
- ✅ 识别"次留"是黑话
- ✅ 翻译为"次日留存率"
- ⚠️ 需要澄清: "最近" 是多久？哪些用户的留存？

---

### 用例 4.3: 多义词

**需求描述**:
```
查询活跃用户
```

**预期行为**:
- ✅ 识别"活跃用户"可能有多种理解
- ✅ 澄清是要"活跃用户数（DAU）"还是"活跃用户列表"
- ✅ 澄清时间范围

---

### 用例 4.4: 知识库缺失

**需求描述**:
```
查询用户的 RFM 得分分布
```

**预期行为**:
- ✅ 识别 RFM 不在知识库中
- ✅ 询问 RFM 的定义和计算规则
- ✅ 询问数据在哪张表
- ❌ 不能自行定义 RFM 规则

---

### 用例 4.5: 需求自相矛盾

**需求描述**:
```
查询新用户的 MAU
```

**预期行为**:
- ✅ 识别逻辑矛盾（新用户通常按日分析，MAU 是月度指标）
- ✅ 询问真实意图
- ✅ 提供合理的替代方案

## 测试执行

### 执行方式

1. **人工测试**: 
   - 逐个输入测试用例
   - 检查 AI 的响应
   - 评分

2. **自动化测试**:
   - 使用脚本批量测试
   - 对比生成的 SQL 与预期 SQL
   - 计算准确率

### 评分标准

每个测试用例 10 分：
- 需求理解: 2 分
- 需求澄清: 2 分
- SQL 正确性: 3 分
- SQL 性能: 2 分
- 输出质量: 1 分

**总分**: 100 分（10 个用例）

**及格标准**: 85 分（85% 准确率）
